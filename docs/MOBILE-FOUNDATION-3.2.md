# Stage 3.2 — Mobile Foundation

Реализовано локально 26 ноября 2026 года по утверждённому [техническому плану](MOBILE-FOUNDATION-3.2-PLAN.md). Этап готов к пользовательской приёмке. Stage 3.3 не начат.

## Результат

Один frontend, один `#module-tabs` и один DOM каждого открытого редактора. Новых зависимостей, роутера, сборщика или параллельной мобильной реализации нет. Backend, API, SQLite, materialization, финансовая модель и административные механизмы не менялись. В `static.go` добавлены только allowlist и embed нового CSS.

- **Desktop:** переключатель модуля слева, равномерно распределённые вкладки в центре, поиск/бэкап/настройки/STG справа. Активная вкладка обозначена голубым текстом и нижней линией.
- **Mobile:** компактный верхний header, меню двух модулей с локальными иконками и отметкой выбора. Существующий DOM вкладок «Планы» становится нижней панелью из четырёх элементов. «Бюджет» сохраняет вкладки, поиск и скачивание бэкапа; нижняя панель планировщика в нём не отображается.
- **Редакторы:** `P.editorShell` на основе `P.dialog` используется для новой и существующей задачи, существующего проекта и нового проекта через `workflow.host`. Desktop — боковая панель; mobile — полноэкранный native dialog. Header/footer не прокручиваются, основная область прокручивается отдельно. Кнопка submit вынесена в footer и связана с исходной формой атрибутом `form`.
- **Общие компоненты:** мобильные размеры полей и кнопок, перенос названий, видимые focus/disabled-состояния, компактные подтверждения. Круг выполнения сохраняет круглую форму с расширенной областью нажатия. Содержимое конкретных бизнес-экранов не перестраивалось.
- **Уведомления:** toast/Undo и компактный статус синхронизации учитывают нижнюю навигацию. В открытом редакторе toast находится в его modal layer перед footer; длинное сообщение ограничено по высоте. Ошибки синхронизации и авторизации остаются видимыми в диалоге.

## Адаптивная архитектура

`navigation.css` отвечает за общую навигацию; новый `foundation.css`, подключённый после существующих стилей, — за адаптивные примитивы и оболочку редакторов. Конфликтующие прежние правила полноэкранных диалогов и двухколоночных форм перекрыты точечными селекторами новой оболочки.

Границы: **до 767 px — mobile; 768–1023 — компактный desktop; от 1024 — desktop**. Адаптация CSS не вызывает запросы, пересоздание формы или смену режима календаря. Существующие календарные границы 700/900 px сохранены.

Сохранена прокрутка документа. Используются `viewport-fit=cover`, `interactive-widget=resizes-content`, `100dvh` с `100vh` fallback и `env(safe-area-inset-*)`. Нижний отступ контента резервирует место панели. Полноэкранный редактор закрывает фоновый интерфейс средствами native dialog; нижняя навигация скрывается. Масштабирование не запрещено, глобального `overflow-x:hidden` и VisualViewport-эвристик нет.

На mobile начальный фокус редактора направлен на заголовок, а не текстовое поле: просмотр карточки сам по себе не должен вызывать клавиатуру. Desktop сохраняет начальный фокус поля. Resize не выполняет повторный focus и не заменяет форму.

## История, черновики и прокрутка

В существующий hash lifecycle добавлены небольшие служебные отметки `history.state.plannerEntry`; другие поля state сохраняются. Новый роутер не создавался.

- Закрытие редактора, открытого из приложения, возвращает на известный предыдущий маршрут. Для прямой ссылки без такого происхождения URL заменяется на `P.panelURL()`.
- Отмена перехода при несохранённых изменениях возвращает исходную history entry без `pushState`, без пересоздания формы и без потери Forward.
- Back при вложенном диалоге сначала закрывает верхний слой и сохраняет редактор. Escape использует тот же guarded close.
- Нормализация календарного URL и изменение фильтров используют `P.replaceRoute`, сохраняя служебную отметку истории.
- Исходные фокус и прокрутка восстанавливаются после завершения reconciliation, когда фон уже выведен из `inert`. Параметры создания редактора исключены из ключа фонового экрана, чтобы открытие новой формы не меняло его идентичность.
- Известные внешние переходы не блокируются глобальным перехватчиком Back. После новой загрузки документа прежняя in-memory история редактора не считается собственной.

Сохранены `P.guardForm`, черновики, проверки ревизий, conflict/uncertain, идентичные повторные команды и существующие обработчики сохранения. Watermark, защита от устаревших GET и финансовый If-Match не изменялись.

Во время проверки обнаружены и исправлены два связанных дефекта: календарный `replaceState(null, …)` стирал отметку history entry, а слишком раннее восстановление фокуса/прокрутки происходило до окончания замены фонового представления. Регрессии для обоих сценариев включены в новый браузерный файл.

## Ограничения и отклонения от плана

Существенных архитектурных отклонений нет. Дополнительно пришлось заменить несколько `replaceState(null, …)` вызовами общего helper: без этого календарь/фильтры уничтожали необходимую для Back отметку. Это изменение только клиентской маршрутизации, без нового роутера.

Физическая OnePlus-клавиатура, системный Back при открытой клавиатуре, поворот, адресная строка Chrome и системные safe areas **не проверены на реальном устройстве**. Эмуляция viewport этого не заменяет. VisualViewport fallback не добавлялся: сначала нужна физическая приёмка утверждённого подхода.

История и черновики живут согласно существующему lifecycle страницы. Восстановление после выгрузки Android-процесса/закрытия вкладки не реализовано. Календарь, настройки, архив и финансовые экраны пока сохраняют существующее содержимое; это общая адаптивная основа, а не завершённый мобильный редизайн всех экранов.

## Ручная приёмка после установки пользователем на STG

**Mac / Chrome:**

1. Открыть базовый URL: месячный календарь. Проверить равномерные вкладки, настройки и STG. Переключить «Планы / Бюджет», открыть категории/аналитику, поиск и бэкап, вернуться на последний раздел.
2. Открыть существующую задачу и проект; создать новые. Проверить боковую панель, Tab/Shift+Tab, Escape и подтверждение несохранённых изменений.
3. Заполнить форму, выделить текст, раскрыть параметры, прокрутить. Изменить ширину через 767/768 и 1023/1024: значения, вкладка, фокус и прокрутка должны сохраниться. Проверить Back/Forward и прямую ссылку на карточку.

**OnePlus 13 / Chrome:**

1. Проверить верхнюю панель, меню модулей, все четыре нижние вкладки, счётчик внимания и последний элемент длинного списка. Отдельно проверить бюджетный поиск и создание синтетического расхода.
2. Открыть существующую задачу: клавиатура не появляется сама. Нажать поле; прокрутить длинную форму и убедиться, что сохранение доступно с клавиатурой.
3. Проверить системный Back: сначала скрытие клавиатуры, затем верхний диалог, затем guarded закрытие формы. Отменить уход, проверить черновик; затем сохранить/закрыть. Проверить поворот и сворачивание адресной строки, pinch zoom и safe areas.
4. Создать длинный проект с задачами, открыть оба типа редактора. Проверить уведомление/Undo, отсутствие перекрытия сохранения и возврат к прежней прокрутке.
5. С Mac изменить открытую на телефоне задачу: черновик не должен исчезнуть; при сохранении устаревшей версии должен быть виден конфликт. Проверить переподключение после краткого отключения сети.

Коммит, установка STG, дальнейший promotion — только пользователем по существующему процессу. В этой работе commit/deploy/promotion и серверные изменения не выполнялись.
