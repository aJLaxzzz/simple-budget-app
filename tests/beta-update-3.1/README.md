# Целевая проверка Beta 3.1

Из корня репозитория:

```sh
go test ./internal/planner -run '^TestBeta31' -count=1
npx playwright test tests/browser/beta31.spec.cjs tests/browser/beta3.spec.cjs tests/browser/series.spec.cjs
```

Playwright сам запускает Go на временной SQLite. Для изолированной съёмки запустите отдельно `BETA31_SCREENSHOTS=1 npx playwright test tests/browser/beta31.spec.cjs`. Снимки записываются в игнорируемый `artifacts/beta-update-3.1/`; пользовательская база не используется. Один HTTP 409 намеренно имитируется в браузере для проверки повторного предпросмотра, другой реальный 409 проверяет запрет совпадения с исходным периодом. Неожиданные `pageerror` запрещены общей фикстурой.

Для проверки согласованного **самостоятельного снимка**, созданного SQLite Backup API (не основного файла активной WAL-базы):

```sh
BETA31_SNAPSHOT=/private/path/snapshot.sqlite go test ./internal/planner -run '^TestBeta31PrivateSnapshot$' -count=1 -v
```

Это опциональная регрессия именно диагностированного случая: она ожидает 70 ошибочных дат и один совпадающий исходный период. Тест читает снимок как файл, создаёт отдельную копию в `t.TempDir()` и изменяет исключительно копию. Реальную рабочую базу сюда передавать нельзя. При другой базе количественные ожидания закономерно не выполнятся. Приватные логи и снимки не публиковать.

`package.py` создаёт сравнение и офлайн-галерею после браузерного теста. Требуется Python с Pillow; на macOS используется системный Arial Unicode. Оригинальные PNG не уменьшаются и не перезаписываются. Базовые снимки показывают синтетическое воспроизведение прежней политики `keep`; новый API уже блокирует создание совпадающего с исходным проектом периода. Для проверки старого совпадения браузерная фикстура отдельно восстанавливает даты исходного проекта через API.
